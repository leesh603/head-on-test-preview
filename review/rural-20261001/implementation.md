# 전원지대 열차포 기믹 구현

기준: 테스트 저장소 `leesh603/head-on-test-preview`, main `70e91c8753d2defc4ee92e8e548bfbc787ed3705` (v481). 작업 중 반영된 도심 포대 배치 수정과 모듈 핀을 그대로 보존했다. 배포는 이 브랜치의 범위에 포함하지 않는다.

## 전투 변화

## 접근·부분 파괴

원본 512×768 이미지 16장(정상8/잔해8)을 재사용한다. 260×390 크기와 비율을 유지하고 객차 중심 간격을155에서375로 늘렸다. 후미 진입 위치는 기존과 같다. 기관차가 앞쪽에 위치해 긴 열차를 실제로 추격하게 된다.

후미→중간→전방 순서로 다음 부위를 연다. 체력은 전달된 본체 예산에서 각각16%/18%/26%를 한 번만 차감하며 기관차40%를 남긴다. 별도의 숨은 객차 체력 예산을 추가하지 않는다. 체력28% 폭주, 폭주 중 보호, 탈선 후 마무리 흐름은 유지한다. 선로를 미리 부수면 기존처럼0.9초 내 탈선한다.

선로 부위는 진입 후미 뒤220의 월드 좌표에 고정된다. 선로 파괴는 이동을 멈추지만 주포 사격을 멈추지 않는다. 파괴한 객차는 독립 좌표에서 짧게 관성 이동 후 멈추고 전투 중 계속 잔해로 남는다. 남은 열차가 잔해 쪽으로 후진하면 정지·조준 후 앞쪽으로 빠져나간다. 폭주는 잔해 반대쪽으로 진행한다.

## 구현 범위

`RuralRailBoss`를 브루노/랑콩파라블에만 연결했다. 공유 `RailAdapter`와 `RailBossController`는 변경하지 않았다. 플리거주크는 기존 전용 기믹·지오메트리·아트를 유지한다.

공유 위험물에 선택형 확장 고리 판정만 추가했다. 풀 재사용 시 고리 필드와 플레이어별 피격 집합을 초기화한다. 다른 원형 위험물은 기존 판정을 사용한다. 새로운 고리·연막은 기존 FX를 사용하며 호스트의 중복 일반 폭발을 얹지 않는다.

## 검증

- 전체164개 테스트 통과. 신규25개: 체력·순서·조준 취소·포탄 수·관측차·탄약차·잔해·선로·재장전·충격파·풀 재사용·플리거주크 보존.
- 실제 `Game`/`CoopGame` 호스트, 양 진영, 일시정지/정리, 모바일120초 전투와 위험물 풀 한도 검증.
- 실제 `drawStageBoss`와 `CoopGame` 호스트를 Native Canvas로 렌더: 변경 전36개 + 개선본36개 =72개, PC1280×800/모바일390×844. Canvas 변환 상태 누수 없음. 개선본 렌더의 누락 이미지 없음.
- `comparison.html`에72개 비교 이미지를 포함했다. 브라우저 실플레이·입력 검증은 수행하지 않았다. 검증용 들판 배경과 상태 진입을 사용한다.
- 원본 열차 이미지16개 SHA가 최신 main과 정확히 일치한다. 다른 파일도 업로드 전 원격 트리 SHA와 대조한다.
- 로컬 정적 검사:122개 모듈 구문 통과,289개 참조 해결. 기존에 로컬 복사본이 없는4개 아트 때문에6개 참조가 누락으로 나온다. 모두 원격 main에 있는 기존 파일이며 `source-check.json`에 경로·SHA·크기를 기록했다. 새 모듈 참조 누락은 없다.

Devin이 테섭에 반영할 때 기존 배포 절차의 빌드/모듈 캐시 핀 갱신을 적용하면 된다. 원본 아트 재업로드나 프로덕션 저장소 수정은 필요하지 않다.
